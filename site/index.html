O Vazamento Silencioso

Uma trava antifraude com 100% de cobertura que, mesmo assim, deixa passar uma fraude de exatamente R$ 10.000 — e como o mutation testing revela o defeito que a cobertura esconde.

A regra de negócio é simples: qualquer transferência de risco de R$ 10.000 ou mais deve ser bloqueada para aprovação manual.

if (valorTransferencia >= LIMITE_APROVACAO_MANUAL) {
  return false; // bloqueado
}

Dois testes (R$ 5.000 aprovado, R$ 15.000 bloqueado) fecham a cobertura em 100%. A esteira fica verde, o "laudo" diz que está blindado. Mas ninguém testou a borda exata dos R$ 10.000 — e é aí que mora o vazamento.

Três execuções reais no GitHub Actions

Sem simulação: cada execução abaixo é um commit que rodou de verdade na pipeline. Clique e veja os logs.

#O que mudouJest / CoberturaMutação (Stryker)
v1 Código correto (>=), 2 testes ✔ 100% verde —
v2 Alteram >= para > no código ✔ 100% verde ✗ mutante sobrevive (88,89%)
v3 Corrige >= + teste da borda ✔ 100% verde ✔ 100%

O coração da demo é o v2: a regra foi quebrada de verdade e, ainda assim, o Jest ficou verde com 100% de cobertura. Só o Stryker reprovou — passo verde e passo vermelho no mesmo run.

A lição

Cobertura de código mede se uma linha executou. Mutation testing mede se um teste falharia caso a regra estivesse errada. São perguntas diferentes — e a segunda é a que importa.

Se uma IA ou um desenvolvedor, por engano, altera ou remove aquela cláusula de proteção, existe um teste que pega a regressão? Se a resposta for não, a cobertura de 100% não vale nada: o defeito entra em produção calado, e só aparece no incidente real.
